# متجر العطاء — الويب (iPhone) + تطبيق أندرويد

تطبيق مستقل يعمل بذاته: موقع ويب قابل للتثبيت على الآيفون (PWA) وتطبيق أندرويد (APK)، بنفس شاشات متجر العطاء وقوائمه وميزاته.
لا يعتمد على أي منصة بناء: ملفاته داخل هذا المستودع، ويُستضاف على Netlify، ويتصل فقط بقاعدة بياناته (Supabase).

| المنصة | كيف تصل للمستخدم | كيف يصله التحديث |
|---|---|---|
| **الويب / iPhone** (PWA) | رابط Netlify ← «إضافة إلى الشاشة الرئيسية» | تلقائياً، بدون أي خطوة من المستخدم |
| **أندرويد** (APK) | ملف APK من صفحة Releases | تظهر داخل التطبيق «يتوفر تحديث جديد» ← «تحديث الآن» |

## مكونات المشروع

- `site/` — ملفات التطبيق الأساسية (الصفحات والتصميم والمنطق) المستقلة داخل المستودع.
- `shell/` — الإضافات: التحديث التلقائي، حائط التمييز، زر «حذف وإرجاع الجميع»، الوضع الداكن، الخط، وإصلاحات أندرويد (حفظ PDF والطباعة).
- `fonts/` — خط Dubai (يُضمَّن مع الموقع، لا يُحمَّل من الإنترنت).
- `android/` — مشروع أندرويد (Capacitor). `scripts/` — البناء وتوليد الأيقونات.
- `config/backend.json` — قاعدة البيانات التي يتصل بها التطبيق (انظر أدناه).
- `supabase/optional-atomic-and-hall.sql` — ترقية اختيارية لقاعدة البيانات (شراء ذرّي وحائط بمشغّل).

عند البناء تُحذف تلقائياً كل مسارات وروابط المنصة التي بُني عليها الأصل، فلا يتصل التطبيق أثناء التشغيل بأي جهة غير خادمه وقاعدة بياناته.

## قاعدة البيانات
**التطبيق يعمل الآن على قاعدة Supabase خاصة به** (مشروع `cmtqqtbmoliydhjorwvz`)، مستقلة تماماً عن أي موقع آخر؛ نُسخت إليها البيانات الأصلية كاملة.

اجعل لتطبيقك قاعدة Supabase خاصة: شغّل ملف SQL الجاهز في مشروعك، ثم ضع الرابط ومفتاح **anon** العام في `config/backend.json`:

```json
{ "url": "https://xxxx.supabase.co", "key": "<anon public key>" }
```

البناء يرفض مفتاح `service_role` ويتحقق أن المفتاح يخص نفس المشروع. إذا ترك الملف فارغاً يبقى التطبيق على قاعدته الحالية.

## كيف تُرفع التحديثات
كل دفع (push) إلى `main`:
1. Netlify يبني الموقع وينشره ← نسخ الآيفون والويب تتحدث لوحدها.
2. GitHub يبني APK موقّعاً (`v1.0.N`) ← التطبيق المثبّت يعرض نافذة «يتوفر تحديث جديد».

لرفع رقم الإصدار الرئيسي غيّر `version` في `package.json`. إصدار يدوي بلا أسرار: ضع APK موقّعاً في `releases/alataa-store-vX.Y.Z.apk` وادفعه.

## الإعداد (مرة واحدة)
1. المستودع **عام (Public)** (ليفحص التطبيق التحديثات بدون مفاتيح).
2. أسرار توقيع أندرويد (*Settings ← Secrets and variables ← Actions*): `ANDROID_KEYSTORE_BASE64` و`ANDROID_KEYSTORE_PASSWORD`.
   > احتفظ بنسخة من ملف المفتاح وكلمته: إذا ضاع فلن يقبل أندرويد تحديث التطبيق المثبّت. لا ترفعه إلى المستودع أبداً.
3. ربط Netlify بالمستودع: *Project configuration ← Build & deploy ← Continuous deployment ← Link repository* (الفرع `main`، والإعدادات في `netlify.toml`).

## الميزات المضافة
- **حائط التمييز** (`shell/hall.js`): مجموع النقاط **المكتسبة** لكل طالب منذ البداية بترتيب المراكز؛ لا ينقص عند الشراء، ولا يُحتسب فيه ما يُعاد للطالب (إرجاع المشرف أو استرجاع نسخة احتياطية). للمشرف زر «نقاط حائط التمييز» لتصحيح المجاميع.
- **حذف وإرجاع الجميع** (`shell/refund-all.js`): يحذف كل الطلبات، ويُرجع الكميات للمتجر، والنقاط للطلاب، ويفتح لهم باب الطلب.
- **الوضع الداكن**: يتبع إعداد الجوال وزر للتبديل في أقصى الزاوية العلوية. **الخط**: Dubai Bold.

## أوامر محلية
```bash
npm install
npm run build         # يبني dist/ (الموقع + PWA)
npm run icons         # يعيد توليد الأيقونات من assets/logo-source.webp
npm run android:sync  # يبني ويزامن مشروع الأندرويد
```
بناء APK (JDK 21 + Android SDK 36): `cd android && ./gradlew assembleRelease -PappVersionName=1.0.3 -PappVersionCode=103` مع ضبط `ANDROID_KEYSTORE_FILE` و`ANDROID_KEYSTORE_PASSWORD`.
